# Protected collection and check publication

The host owns the approved registration, verifier installation, workflow identity and credentials. The candidate owns none of those. The APIs below are explicit integration components; a workflow naming itself protected grants no authority.

## Approved baseline and nested projects

`loadRegistration(projectRoot, path, protectedDigest)` reads an owner-private snapshot outside the entire candidate Git checkout. `registrationProjectData(registration)` translates only the selected Git subtree into project-relative paths, preserving the actual commit and semantic hashes. `source.projectPath: "."` means the Git root. An obligation or input outside the selected subtree is an error, not a silently dropped requirement. The projection is data conversion; it does not authenticate an arbitrary supplied object.

The actual PR7 source at `5cb1133e45d3fe73974401d8c666ad1eab6fff78` was checked out and every enrolled file hash matched the externally registered baseline. The public Collector, new worker and built CLI then accepted its human baseline, comparisons, per-case target observations and canaries under an explicit local host. See `docs/evidence/approved-probe-live.json`. Its full critical gate remains incomplete because coverage, sufficient mutation-score evidence and external pipeline protection are absent.

## Scoped production probes

`instrumentFunction({source,targetRef,expectedSourceHash,faultValue})` from `@behavproof/contract-registry` generates two separate programs for a named exported TypeScript function declaration. The ordinary program retains the production body and records calls through `@behavproof/vitest/probe`; the fault program replaces only that function body with the selected distinct JSON value. Unsupported syntax/targets or source mismatch stay unknown. This narrow reference supports the authorization example; it is not general method, arrow, generator or call-graph support.

The official test helper captures observations in each callback's asynchronous context. A normal callback can reach the target; `({expected}) => expected` can pass comparisons while providing no target observations. The raw records are diagnostic claims, not authority.

`evaluateProbeRuns(protocol, verifyRun)` separately matches current contract revision, complete cases, actual registration/binding identities, observations and real failed comparisons from a fresh fault run. Test IDs may differ across isolated directories; binding/revision/case multisets must agree. A nonzero process exit alone, missing case, changed callback, old source, unverified diagnostic or Promise returned from verification cannot establish sensitivity. The expected-failure run is never successful ordinary test evidence.

The explicit reference worker is `scripts/protected-probe-worker.mjs --request /protected/request.json`. The host selects the clean Git subject, input inventory, effective policy hash, source hash, complete contracts and tests. Wrap it with the public `collect(options)` API. The worker runs actual Vitest with a generated config, pinned SDK helper/probe aliases, no candidate config execution and a minimal child environment. It disables Vitest filesystem/module caches and checks a phase-specific transformation receipt: reusing an earlier transformation cannot establish the newly selected fault. An unused/removed production import produces no receipt and no positive reach claim. Collector seals ordinary reports, separately scoped claims and fault diagnostics only after the wrapper completes; ordinary failure/skip seals no success artifacts.

Run `node scripts/protected-probe-flow.mjs` for actual normal/fake/fault/skip/removal scenarios. This is local host evidence. It makes no CI, human-review or external-protection assertion. Instrumented runs do not supply line coverage or an aggregate Stryker mutation score; those require separately authenticated reports with verified mappings.

An independent CI producer must isolate candidate execution at the OS boundary: credential-free container/VM, network disabled, read-only verifier and source mounts, fresh writable output only, bounded resources and cleanup of descendants on timeout. The Node wrapper itself is not a sandbox. Arbitrary hostile JavaScript can forge metadata inside its own test process; these probes make scoped observations in the selected runner, not a general anti-forgery proof. Do not expose publisher credentials, host private directories, Docker sockets or deployment secrets to that runner.

## Final-gate authority and publisher

A completed evidence producer and the final gate are separate executions. The producer is verified through `GitHubAuthority.producer` against the registered workflow SHA/path, completed successful run/attempt/job and independently downloaded artifact digest/bytes. The final gate must not wait for its own run to finish.

`GitHubAuthority.upstream(ci, expected)` reads the latest attempt plus exact attempt/job identities and requires every selected upstream job to have completed with `success`. The final-gate job may be running. Skip, neutral, failure, cancellation, ambiguous names or another attempt remain unknown. `pipeline.currentRun` in the external trust root selects this path with `ci`, `workflowPath`, `workflowSha` and `workflowHash`. The host must independently bind that hash to the actual trusted workflow source at that SHA. It uses retained authenticated artifact references and has no legacy-report success fallback when live authority is unavailable.

`prepareCheckPublication(packet, expected, verifyPacket)` from `@behavproof/adapter-github` re-evaluates a gate report, checks the complete host-selected global/scoped obligation inventory, subject, effective policy, registration digest, producer identity, upstream outcomes and artifacts. Only strict synchronous `true` from an independent exact-packet verifier grants authority. Obtain run/attempt/job/archive expectations from the protected control plane, never the packet itself. Prepared handles are immutable and cannot be restored from serialized JSON.

`new GitHubCheckPublisher({repository,token}).publish(prepared)` executes no candidate code. It rechecks the repository, current PR head/base and issuer-bound strict/admin branch protection before posting fixed diagnostic text. It emits only success or failure and validates the returned check identity/App. GitHub Actions App15368 is rejected as the dedicated issuer. The App needs Checks write, repository/PR read and access to the required protection metadata; missing protection access produces failure. Keep this credential in the separate protected publisher environment.

A skipped GitHub Actions job may count as a successful required check, so requiring its name alone is insufficient ([GitHub status checks](https://docs.github.com/en/pull-requests/reference/status-checks)). Require the dedicated context and its expected App ID, protect publisher/verifier source and environment, then test actual skip/deletion/same-name wrong-issuer behavior. The new publisher tests use API fixtures; they are not live issuance or merge-enforcement evidence. [GitHub Checks API](https://docs.github.com/en/rest/checks/runs) documents the App issuer and write permission requirement.

## Reproducible sandbox staging

`node scripts/prepare-sandbox-sdk.mjs --output /private/tmp/behavproof-sdk` stages only tracked SDK build inputs, the worker and templates outside the entire Git checkout. It excludes the original specification, private ledger, Git metadata, user settings and host dependencies; it refuses existing output and removes an incomplete stage on failure. Build that source inside the pinned Linux image with `npm ci --ignore-scripts` and `npm run build`. On an already built Linux SDK, `--built` additionally stages compiled artifacts and the lock-listed installed dependencies, rebasing internal links and rejecting outside links without following them. The installation must match the selected verifier and Linux image architecture. Installed dependency contents are a trusted public installation from the protected lock; staging does not scrub arbitrary private files placed inside an allowed dependency.

`node scripts/protected-probe-flow.mjs --sandbox-sdk /private/tmp/behavproof-sdk` runs all five scenarios through a network-disabled, read-only, non-root container with fresh writable output, resource limits and checked cleanup. Before mounting, the SDK path is canonicalized and rejected if it points anywhere inside the entire verifier checkout, including through an alias. Its owner must be the non-root host user, with a private directory mode; tracked source and executable hashes must match the selected verifier. Unlisted private files, outward dependency links and a symlinked dependency root are rejected. Its fixture checks that no external network interface exists and source writes are denied. Only the mounted Git root receives a command-environment ownership exception; the host Git configuration is untouched. Each Vitest phase receives a fresh empty home/config/cache location instead of host home state. `docs/evidence/protected-probe-sandbox.json` records the actual local container run. The root CI adds this runtime stage on Linux; library/public-flow verification remains three-platform.

One claim scope per contract is currently supported. Duplicate contract scopes or case IDs are configuration errors, so an additional target can never be silently ignored by selecting the first entry. Model multiple independently required targets with separate contracts or an explicitly reviewed future aggregation protocol.

The main-only workflow templates and concrete control-plane scripts are described in [protected-github-deployment.md](protected-github-deployment.md). They are a deployment proposal until the actual human enrollment, main integration, App read grants, protected variables and isolated-base enforcement tests are complete. `prepareFailedCheck(identity)` provides an opaque failure-only publication path when producer evidence is absent; it never manufactures a subject or producer CI and cannot publish success.
